2. DynamoDB Schema & Query Optimization

To eliminate expensive table scans, the table uses a composite key pattern:

  • Partition Key (HASH): localityId (String)
  • Sort Key (RANGE): timestamp#reportId (String)

All locality queries execute directly via indexed Query calls on the partition key, yielding consistent 10–15 ms response times.
